### ASan Finding: global-buffer-overflow in VIVID_REGISTER macro

**Reports**: 3 instances, all the same pattern:
```
ERROR: AddressSanitizer: global-buffer-overflow on address 0x... at pc 0x...
WRITE of size 8 at 0x... thread T0
  #0 std::vector<...>::vector() vector.h:548
  #1 std::vector<...>::vector() vector.h:134
  #2 _vivid_get_descriptor() <operator>.cpp
  #3 vivid_descriptor <operator>.cpp
  #4 vivid::OperatorLoader::load() operator_loader.cpp:234
```

**Location**: `s_label_storage` is a `static std::vector<std::vector<std::string>>` inside `_vivid_get_descriptor()`, generated by the `VIVID_REGISTER` macro in `src/operator_api/operator.h`.

**Analysis**: The overflow is reported during the vector's **constructor** (not during a write to vector contents). This occurs when `OperatorLoader::load()` calls `vivid_descriptor()` on a dynamically loaded `.dylib`. ASan reports the global variable as "size 24" (= sizeof(std::vector) on arm64) and flags the write as overflowing.

**Likely classification**: **False positive due to ASan + dlopen interaction on macOS**. ASan tracks global variables by their size in the symbol table. When a `.dylib` is loaded via `dlopen`, ASan may not correctly account for the full static storage of function-local statics, especially when the static is a complex C++ type whose constructor runs lazily. This is a known limitation of ASan with dynamically loaded code on macOS/arm64.

**Evidence supporting false positive**:
- The overflow is at offset 0 (start of the variable), not past its end
- The variable size (24 bytes) matches `sizeof(std::vector)` exactly — ASan sees only the vector header, not the heap-allocated storage
- The same code runs correctly without ASan in all other test suites
- All 75 other tests pass without any ASan reports

**Recommendation**: Not a release blocker. If this were a real overflow, it would crash without ASan. The finding should be revisited if ASan's dlopen tracking improves, or by running ASan with `detect_odr_violation=0` and `ASAN_OPTIONS=intercept_load=1`.
